Hello Wattson

The curriculum site students read in class, gated by a code instead of an account.

What it is

Hello Wattson publishes our workshop programs: the Arduino, web development, LEGO SPIKE and Python material students follow on classroom devices while an instructor runs the room. Public pages describe each program, while lesson pages and teacher files sit behind an access code a teacher hands out. It's 20 programs and 54 lessons so far.

Constraints

A classroom is thirty devices sharing one school IP address, often on slow wifi, with no time to install anything. Students cannot have accounts. Program pages label themselves upcoming, running, or finished, and those labels have to be right on a morning when nobody has touched the site in weeks.

Architecture

The Worker runs ahead of the files it serves, so a gated lesson is never handed out and then hidden. A build served without the Worker would give everything away, which is why the deploy path is fixed.

Decisions I made

  • The access check happens on the server, before any lesson content leaves it.
  • The rate limit counts only failed code attempts. One student mistyping the code cannot lock out the thirty classmates sharing that school IP address.
  • Analytics are cookie-free and aggregate. I can see that a lesson gets used without following anyone through it.
  • Astro 6 with MDX content collections, hand-written CSS, and no client-side framework, because pages load on whatever hardware the school owns.
  • A nightly rebuild at 06:00 UTC regenerates the site, so program status derived from dates stays correct without anyone remembering to edit it.
  • gitleaks scans the full history in CI, so a real access code can never be committed by accident.

What I decided not to build

No student accounts, of any kind. That is a standing rule across every tool I build for the program, and this site is where it costs the most. Accounts would give us saved progress, per-student work, and a class view for teachers. They would also make us the keeper of a directory of children, with logins to reset and a breach to plan for. The unit of access is a code a teacher hands out, and the student stays anonymous to us.
