Hello Wattson

Lessons and coding tools for classrooms, opened by an access code instead of an account.

What it is

Hello Wattson is where we publish our teaching material: 22 programs of Arduino, web development, LEGO SPIKE and Python lessons, plus the coding tools students use beside them. A teacher anywhere can browse the public catalogue, then unlock the lessons with an access code they hand to the class. The site stores nothing about students: no accounts, no names, and no saved work on our side.

How it grew

It started as an internal Eleventy site our own instructors projected in class. Over 2026 it became something teachers outside the program can run themselves.

  • July 2026. I moved the site from Eleventy to Astro 6, keeping every existing URL, and put a Cloudflare Worker in front of it that checks the access code on the server before any lesson leaves.
  • July. A public catalogue and undated tracks, so a teacher outside our program can preview a module and run it on their own schedule, plus a plain-language privacy page.
  • September. Classroom codes moved out of git into Workers KV. Each code lists its modules, a label and an optional expiry, and one command-line tool issues, lists or revokes codes without a redeploy.
  • September 20. A LiveCodes playground on its own origin, play.hellowattson.ca. Student code runs entirely in the browser and saves to the device.
  • October. Pixel Club and Gadget Club, weekly Saturday clubs whose sessions open on their own dates. Reading pages became idea-card decks that show one idea at a time.
  • October 24. An Arduino editor in the browser, with a compile service behind it, launched with Gadget Club’s first session.

Constraints

A classroom is thirty devices sharing one school IP address, often on slow wifi, with no time to install anything. Students cannot have accounts. Program pages label themselves upcoming, running, or finished, and those labels have to be right on a morning when nobody has touched the site in weeks.

The no-accounts rule is also what lets the site reach outside our own rooms. BC public schools work under FIPPA, the provincial privacy law, and a tool that stores student personal information brings privacy-impact paperwork before a teacher can use it. A site that stores nothing about students gives a district privacy officer one page to read instead of a review. Accounts would give us saved progress and a class view for teachers. They would also make us the keeper of a directory of children. The unit of access is a code, and the student stays anonymous to us.

Architecture

The Worker runs ahead of the files it serves, so a gated lesson is never handed out and then hidden. A build served without the Worker would give everything away, which is why every deploy goes through it. The rate limit counts only failed code attempts, so one student mistyping cannot lock out the classmates sharing that school IP address. The playground is a separate Worker with no gate and no secrets, and a first-party subdomain is less likely to be blocked by a school content filter than a third-party domain.

Arduino in the browser

School laptops can’t install the Arduino IDE, so Gadget Club students write sketches in a browser editor with Verify and Upload buttons, the IDE’s own words. Verify sends the sketch to a compile route that needs an unlocked session and is rate-limited per IP address. A Durable Object holds up to 30 waiting compiles in front of a container running arduino-cli with internet off, and accepts only a short list of libraries. Upload flashes the result to the board over Web Serial with our own uploader, so the editor needs Chrome or Edge. Common compiler errors come back as one plain line naming the line number, with the raw text folded underneath.

Before launch I tested it at class size on staging: 25 compiles sent at once waited at most 44 seconds, because one instance compiles one sketch at a time. A hardware flash test on a real Uno passed on Linux. The Windows club laptop and a Chromebook are next.

What’s next (planned)

None of this is built yet. In order: a teacher layer, with a “For teachers” section per module, teacher downloads scoped to the module a code unlocks, and free preview lessons; self-check quizzes that grade in the browser and store nothing; JupyterLite notebooks for Python; and simulator embeds for the hardware modules.
