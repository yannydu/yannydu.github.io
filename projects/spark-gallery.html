Spark Gallery

A published gallery of summer camp work, built so no child's real name ever reaches the cloud.

How it was built: I frame the problem and make the architecture and privacy decisions; Claude Code writes much of the code.

What it is

Every week of camp produces photos, code projects, and videos. Spark Gallery turns that week into a published issue families can open from a link, with each camper getting their own page. Instructors upload from the camp room as the week runs, and I pull each camp in when it finishes and publish. Since October, students in our after-school clubs can also save their club work to it. Live since June 2026, with 11 weekly issues and 497 projects published as of November 2026.

Dev log

Oct 21 to Oct 28, 2026: club saving

Problem
A gallery upload token can also read the roster and delete files, so no token could sit on a student laptop.
Changed
Gadget Club and Pixel Club students now save their work to the gallery, signing in with a code from a printed club card, one card for both clubs. The hello-wattson Worker checks the club session and forwards each save server to server to a write-only club route.
Result
The browser never holds a gallery token.

Sep 11, 2026: a camera in the upload tool

Problem
Instructors uploaded photos through a file picker, and I wanted them to be able to upload easily.
Changed
The upload page gained a camera mode, so a camp laptop takes photos directly. Scanning a QR code jumps to a camper’s upload link, and photos taken before a camper is picked wait in an unsorted tray.

Jul 30 to Aug 5, 2026: privacy checks that stop the run

Problem
A privacy check could fail without stopping the publish.
Changed
A review of the publish and ingest path, in six work packages, turned the privacy checks into gates that fail closed. They are a personal-information scan, a name guard, a publish gate, orphaned-file cleanup in storage, and a written runbook for family withdrawals.
Result
A failed check now stops the publish.

Jul 12, 2026: a name-free pipeline

Problem
A privacy consultation held that a first name and last initial is personal information for children.
Changed
Campers now get their nicknames on my computer before camp starts, and file names are replaced with random codes on arrival. The curator tools merged into one app, Curator Studio, and the instructor upload page went behind an access gate.
Result
The upload area only ever holds nicknames and random codes. As our response memo put it, nothing name-bearing remains online.

Jun 28, 2026: the archive out of reach

Problem
The internet-facing upload code could reach the bucket holding the permanent camp archive, held back only by checks in the code.
Changed
The upload inbox moved to its own bucket, the only one the upload code is bound to.
Result
The public surface cannot reach the archive at all.

Jun 16 to Jun 27, 2026: a sandbox for test data

Problem
Test data had reached production. I wanted production to hold only real camp data.
Changed
Test and training camps moved to a sandbox environment with its own database and storage. A one-time script purged the test data from production.
Result
By Jun 27, production and sandbox shared no resource.

Jun 12, 2026: projects on their own origin

Problem
An iframe sandbox gave each game an opaque origin where localStorage throws, so every game crashed before it loaded.
Changed
Camper projects moved to a separate origin, spark-projects, and instructors got an upload page.
Result
On its own origin a game runs as a normal website and its saves persist.

Jun 8, 2026: a magazine on Cloudflare

Problem
It was our first app open to the public, so I wanted it to have its own style that matched our programs.
Changed
The site moved from GitHub Pages to Astro on Cloudflare Workers with a D1 database. It took a magazine layout: each camp week is an issue with a cover, and each camper has a page.
Result
A day later, one command published a camp from the private archive.

Apr 23, 2026: the first design

Changed
I had an idea for a place that shows what kids build at camp, where families can share the work and people curious about our programs can see past camps. The first commit was a design for it.

Constraints

A privacy ruling meant children's real names could not sit on the cloud provider in any form, not even for the days between upload and publish. Instructors are camp staff, so the upload path had to be a link and a printed sheet. Families needed to browse without an account.

Architecture

The upload tool is part of the gallery app, behind an access gate. Camper projects are served from a separate origin, spark-projects, so a game never shares an origin or cookies with the gallery. Club students save through the hello-wattson Worker, which forwards to a write-only route, so the browser never holds a gallery token. Real names stay on my machine and on paper, with encrypted copies of the name list kept on SFU OneDrive, never on Cloudflare. What travels online is a folder named by a random identifier and a nickname. Stack: Astro on Cloudflare Workers, with D1 (database) and R2 (file storage).

Decisions I made

  • Nicknames are assigned locally before camp starts, so the upload path never receives a name it would have to strip.
  • A pre-push git hook fails closed when a real name appears in files headed for the repository. It stops the push rather than warning.
  • Video is re-muxed through ffmpeg before publishing, which drops the location and device metadata phones attach. CI installs ffmpeg so that step stays tested.
  • gitleaks scans the full history on every CI run, not only the newest changes.
  • Test publishes go to a separate sandbox environment, so invented data can never land beside a real camp.

What I decided not to build

I didn't build accounts for campers or for families, since the site only runs a few weeks each summer and an account would mean holding family contact details and a password reset path year round for that. A link and a nickname cover what families want, which is seeing their kid's work. Club students get a printed code instead, which only lets them save their own work.
